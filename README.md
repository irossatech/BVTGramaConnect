# BVTGramaConnect

The web side of BVT Grama Connect, in one repo:

| App | Folder | Served at | Prototype |
|---|---|---|---|
| Public website, no login | `src/` | `/` | `Public Website.dc.html` |
| Super Admin console | `console/` | `/console/` | `Super Admin Console.dc.html` |

Both are the approved prototypes, ported as is. They are Design Canvas pages: a template plus a logic class, compiled in the browser into React 18 by `support.js`. Only data and actions changed: mock data now comes from the REST API in BVTGramaConnect_BackEnd. Why they are ported this way: the BackEnd repo's `docs/prototype-inventory.md`, section 5.

## Layout

```
src/                      website: index.html, gc-api.js, assets/icon-location.png
console/
  src/                    console: index.html (generated by port.py), gc-api.js
  tools/                  logic.js (the console's logic class), port.py, visual-check.mjs, visual_diff.py
  docs/visual-check/      console screenshots and difference report
shared/                   files identical for both apps
  support.js              Design Canvas runtime, never edited
  vendor/                 React 18.3.1 and ReactDOM 18.3.1 UMD (same files and SRI hashes the runtime expects)
  _ds/…/                  design-system CSS and components from the prototype
  assets/                 logo, village photo, category icons
  config.js               development defaults: API base and console URL
tools/visual-check/       website screenshot and compare scripts
docs/visual-check/        website screenshots and results
build.mjs                 builds both apps
.env.example              build settings
```

## Build

Node 18 or newer. No npm packages are needed.

```
npm ci
npm run build
```

This writes `dist/` (website) and `dist/console/` (console). Each gets `shared/` plus its own files, at the same relative paths the pages use, and a `config.js` generated from these settings:

| Variable | Default | Meaning |
|---|---|---|
| `GC_API_BASE` | `/api/v1` | Base URL of the API both apps call |
| `GC_CONSOLE_URL` | `/console/` | Where the website's "Admin Login" leads |

Set them in the environment, or copy `.env.example` to `.env`. `dist/` and `.env` are git-ignored. Files are copied byte for byte: the runtime re-reads `index.html` on boot, so nothing may minify or rewrite it.

## Run locally

1. Clone BVTGramaConnect_BackEnd next to this repo. In it: `python manage.py migrate`, `python manage.py seed_sample_data` (prints usernames and temporary passwords) and `python manage.py runserver`.
2. Here: `npm run build`.
3. Open http://127.0.0.1:8000/ for the website and http://127.0.0.1:8000/console/ for the console. Log in to the console as `super.admin` with the printed password; it asks for a new password first.

Django serves `dist/` at `/` (`WEB_PUBLIC_DIR`, default `../BVTGramaConnect/dist`) and `dist/console/` at `/console/` (`WEB_ADMIN_DIR`, default `../BVTGramaConnect/dist/console`) while DEBUG is on.

## What changed from the prototypes

**Website**, only the changes allowed by the inventory, section 5.4:
1. `<html data-ds-base="assets">`, so design-system icons resolve.
2. Script tags for `vendor/react…`, `vendor/react-dom…`, `config.js` and `gc-api.js` before `support.js`. React loads from this site, not unpkg. `window.__resources` is never defined.
3. Contact details come from `GET /api/v1/public/site-config/`; the prototype's values are the defaults.
4. Store buttons open `play_store_url` and `app_store_url`; while a URL is empty they show the prototype's "coming soon" toast.
5. The contact form posts to `POST /api/v1/public/contact-messages/`, with an invisible honeypot input. Two toast texts were added in Telugu and English.
6. "Admin Login" sends officials to `/console/`.

The phone mockup in the hero stays a static illustration on purpose (open question Q16).

**Console:** every mock dataset now comes from the API. Additions, in the prototype's own inline styles: username and password login, a change-password screen, server-side paging, loading and empty rows, reset password, email and username in Add User, CSV import for villages, a "Default passwords by role" card, and an "Already decided by …" toast for review conflicts. Full list: `.claude/architecture.md`.

## When the designer re-exports the console

```
npm run port:console        # python console/tools/port.py "<prototype folder>"
npm run build
```

`port.py` applies each change as an exact text replacement and stops if one no longer matches, so a moved element cannot slip through. It also refreshes `shared/` from the prototype.

## Console sign-in and session

- Username or email plus password, `client: "web_admin"`; only Super Admins get in.
- The access token is kept in memory only. The refresh token is an HttpOnly, Secure, SameSite=Strict cookie (`gc_refresh`, path `/api/v1/auth/`) that page scripts never see. A page reload refreshes the session through that cookie.
- CSRF: the cookie is only sent on same-site requests and the server also checks the Origin header on the cookie routes. Every other request carries the bearer token.

## Visual checks

`docs/visual-check/` (website, 375 px and 1280 px) and `console/docs/visual-check/` (console, 1440x900) hold prototype-versus-port screenshots and difference reports. How to re-run them: `.claude/operations.md`.

## Deploy

The BackEnd repo's `deploy/deploy.sh` clones this repo on the server, builds it once and publishes `dist/` at `/` and `dist/console/` at `/console/` through Nginx. The pages need a Content-Security-Policy with `script-src 'self' 'unsafe-eval'` and `style-src 'self' 'unsafe-inline' https://fonts.googleapis.com`.
