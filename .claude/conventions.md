# Conventions: website and console

## Zero visual change

Both apps must look and behave exactly like the approved prototypes. Only these changes are allowed (BackEnd repo, `docs/prototype-inventory.md`, section 5.4):

1. Each page file is `index.html`. The runtime takes its root name from the file name, so the name does not matter.
2. Script tags in `<head>`, before `support.js`: `vendor/react…`, `vendor/react-dom…`, `config.js`, `gc-api.js`.
3. `window.__resources` is never defined.
4. `data-ds-base="assets"` on `<html>`.
5. Data wiring only in the logic class: mock values become `state` filled from the API. Loading and error states reuse what the page already has, such as the toast. No new layout.
6. Hard-coded values in the template become `{{ }}` bindings.
7. Demo-only controls are removed or pointed at the real target.
8. Markup, inline styles, CSS files, fonts, images and animations stay as they are.

The console also has the documented additions listed in `architecture.md` ("Console"). Anything else, including new text or a new section, is a design change and needs the owner's sign-off first.

## Where to make a change

| Change | Edit | Then |
|---|---|---|
| Website behaviour, data, text | `src/index.html` (logic class, dictionary, `{{ }}` bindings) | `npm run build` |
| Website fetch helper | `src/gc-api.js` | `npm run build` |
| Console behaviour, data, API calls | `console/tools/logic.js` | `npm run port:console`, then `npm run build` |
| Console markup | `console/tools/port.py`, as a new exact replacement or checked line edit | same |
| Console fetch, session login, CSRF | `console/src/gc-api.js` | `npm run build` |
| API base URL or console URL | nothing; set `GC_API_BASE` / `GC_CONSOLE_URL` in the environment or `.env` | `npm run build` |

## Files you never edit

- `shared/support.js`: generated runtime. If the designer re-exports, replace the file whole.
- `shared/vendor/*`: React 18.3.1 exactly as published. Their hashes must match the SRI hashes in `support.js`.
- `shared/_ds/`: design-system files from the prototype.
- `console/src/index.html`: generated by `port.py`.

## What goes in shared/

Only files that are byte-identical for both apps: the runtime, React, the design system, common images and the `config.js` template. A file only one app uses stays in that app's folder (for example `src/assets/icon-location.png`). Each app keeps its own `index.html` and `gc-api.js`. If an app ever needs a different version of a shared file, move it back into that app's folder rather than changing it for both.

## Text and languages (website)

- Every string lives in `Component.T` with a `te` and an `en` entry under the same key. Add both or neither.
- Telugu is the default language (`lang: 'te'`).
- Do not "fix" the hero subtitles: the Telugu one is an English sentence and the English one starts in Telugu, on purpose.
- Files are UTF-8. Check Telugu on screen after every change.

## Console rules

- New console UI reuses an existing element's inline style: copy the pill button, input, card or table-row style from the nearest similar element. Add no stylesheet, class or font.
- Keep the template bound to the same keys; map API data into those shapes in `logic.js` instead of changing the template.
- Every request goes through `window.GC_API` (`this.api`). Do not call `fetch` directly. Report errors with `this.fail(e)`.
- Never store a token or password in `localStorage`, `sessionStorage` or a readable cookie. The console's only readable cookie is Django's `csrftoken`.
- The console only hides buttons. The backend enforces every permission.

## API changes

The BackEnd repo's `docs/api-contract.md` is the source of truth. If either app needs a new endpoint or field, the backend team adds it to the contract first; then update `.claude/api.md`.

## Checking a change

1. `npm run build` and open both apps through the backend's runserver.
2. Website: click every page in both languages at 375 px and 1280 px wide.
3. Console: log in as `super.admin` from `seed_sample_data` and click through every screen.
4. Rerun the visual check for any change near the markup (steps in `operations.md`). Website results go to `docs/visual-check/`, console results to `console/docs/visual-check/`. Investigate every difference that is not real data or a documented addition.

## Git

Branch from `dev`, open a pull request into `dev`. Never commit `dist/` or `.env`. Keep `package-lock.json` committed.
