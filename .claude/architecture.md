# Architecture: website and console

One repo, two apps, one build.

| App | Source | Built to | Served at |
|---|---|---|---|
| Public website | `src/` | `dist/` | `/` |
| Super Admin console | `console/src/` (generated) | `dist/console/` | `/console/` |
| Files both apps use | `shared/` | copied into both outputs | |

## Folder map

```
src/                      website: index.html, gc-api.js, assets/icon-location.png (website only)
console/
  src/                    console: index.html (generated by port.py), gc-api.js
  tools/                  port.py, logic.js, visual-check.mjs, visual_diff.py
  docs/visual-check/      console screenshots and difference report
shared/                   identical for both apps
  support.js              Design Canvas runtime ("dc-runtime"), never edited
  vendor/                 React 18.3.1 and ReactDOM 18.3.1 UMD
  _ds/…/                  design-system CSS, tokens and _ds_bundle.js (plus design-tool metadata)
  assets/                 logo-mark.png, village-landscape.jpg, four category icons
  config.js               development default: { apiBase, consoleUrl }
tools/visual-check/       website screenshot and compare scripts
docs/visual-check/        website screenshots and results
build.mjs                 builds both apps
```

## Both pages are Design Canvas pages

| Part | Where | What it does |
|---|---|---|
| Template | `<x-dc>` block in each `index.html` | HTML with inline styles, `{{ expr }}` bindings, `<sc-if>` / `<sc-else>`, `<sc-for list as>` loops, `onClick="{{ handler }}"`. `<helmet>` holds head links. |
| Logic | `<script type="text/x-dc" data-dc-script>` in each `index.html` | `class Component extends DCLogic` with `state`, `setState`, `componentDidMount` and `renderVals()`, which returns every value the template binds to. |
| Runtime | `support.js` | Compiles the template into React elements in the browser and evaluates the logic class with `new Function`. |
| React | `vendor/` | React 18.3.1 UMD, the same files and SRI hashes the runtime would fetch from unpkg. Loaded before `support.js`, so the runtime skips its CDN download. |
| Config | `config.js` | `window.GC_CONFIG = { apiBase, consoleUrl }`, generated by the build. |
| API helper | `gc-api.js`, one per app | Website: `window.GCApi.get/post`. Console: `window.GC_API` with the session login, the CSRF header and downloads. |

Each page's `<head>` loads React, ReactDOM, `config.js`, `gc-api.js`, then `support.js`. `<html data-ds-base="assets">` tells design-system components where images are. All paths are relative, so each app works from its own folder.

Each page is its own document. Their global CSS (`:root`, `body`, links, inputs) never meets, and their animation names differ (`mk-` for the website, `sa-` for the console). No CSS scoping is needed.

## Two runtime facts that shape every change

- **The runtime re-reads its own page.** On boot `support.js` fetches `index.html` again to read the raw template, because the browser's HTML parser moves `<sc-for>` out of tables and selects. The console relies on this in six tables and two selects. So `index.html` must be served byte for byte: no minifier, no rewriting proxy.
- **Never define `window.__resources`.** When it exists, the runtime skips that re-read and assumes a bundled export, and templates with loops inside tables or selects break.

## Website

- `src/index.html` is the approved prototype `Public Website.dc.html` with the allowed port changes.
- Pages switch in component state (`state.page`): `home`, `how`, `officials`, `faq`, `contact`, `admin`. `go()` pushes `#<page>` (home: no hash) onto the history, and `hashchange` and `popstate` set the page from the hash, so links like `/#faq` open that page and Back and Forward work. Below 820 px a ResizeObserver switches to the mobile layout.
- The Telugu and English dictionary is `Component.T`. Telugu is the default.
- Data: on mount `GET /public/site-config/` fills the office details and store links; the Contact form posts to `POST /public/contact-messages/`. `GET /public/showcase/` fills the hero's phone picture through the `phone` and `miniCards` render values, cached per language; the prototype's static values are the fallback.

## Console

The console page is generated, never edited by hand:

```
prototype folder (read-only)          console/tools/logic.js     console/tools/port.py
  Super Admin Console.dc.html   +     the logic class       =>   console/src/index.html
  support.js, _ds/, assets/           wired to the API           shared/support.js, shared/_ds/, shared/assets/, shared/vendor/
```

- `port.py` applies every change as an exact text replacement or a checked line edit. A replacement that no longer matches exactly once stops the script, so a designer re-export cannot drift silently. It finds the prototype folder three levels above `console/tools/`.
- `logic.js` holds all behaviour. Loaders per page call the API through `this.api` (`window.GC_API`). Adapters turn API objects into the exact view-model shapes the prototype's template binds to, so the template stays as designed. Static maps translate API enums such as `UNPUBLISHED` into prototype keys such as `TakenDown`. `fail(e)` is the single error handler.
- **Sign-in:** username and password through a Django session. `gc-api.js` first calls `GET /auth/csrf/` for the readable `csrftoken` cookie, then `POST /auth/session/login/`; the server sets the HttpOnly `sessionid` cookie, so page scripts never see a token. Every call is same-origin with cookies, and every write sends `X-CSRFToken` (read from the cookie on each request, because Django rotates it at login). On page load the console calls `GET /me/`; a 401 keeps the login screen. Only users with `web_admin.access_web_console` get in. When `must_change_password` is set, the change-password card comes first; the same card opens from "Change password" in the profile menu, with "‹ Back" instead of "‹ Sign out". A 401 from any call (idle timeout, logout elsewhere, block, password reset) returns to the login screen with "Your session has ended".
- **Permissions:** `GET /me/` returns `permissions` as `app_label.codename` strings. `logic.js` hides sidebar pages (`NAV_PERM`), Add User and its role choices (`accounts.manage_*`), Settings in the menu, Audit Export CSV and the user panel's buttons (the user's `allowed_actions`). A missing list means no permissions. The server still enforces every action.
- **Additions to the prototype**, all in the prototype's own inline styles: username and password fields; the change-password card; a pager under Users, Posts and Audit (server-side, 20 per page); empty and loading rows; "Reset password" in the user panel; a Roles list with Remove and "+ Add role" in the user panel; a Contact messages page after Audit Log, built like the Audit Log page; Urgent and event chips, a video player and Mark urgent in the post panel; one Export CSV handler per report and no Export PDF; labels for every audit action key; Username, optional Email and Mobile, and "Temporary password (optional)" with Generate in Add User; "Import CSV"; "Change password" in the profile menu; Reset password (a dialog with Generate) and Unlock in the user panel; a dialog that shows a temporary password once, with Copy and no Cancel; bindings for the signed-in name, state name, category filter and real photos. A `409 already_decided` review answer shows in the existing toast.
- The console is a fixed 1440 px canvas, as designed.

## Build and serving

- `npm run build` (`build.mjs`, no npm packages) deletes `dist/`, then for each app copies `shared/` and the app's own files into its output and writes `config.js` from `GC_API_BASE` and `GC_CONSOLE_URL` (environment first, then `.env`). Files are copied byte for byte. `dist/` is git-ignored.
- **Development:** the BackEnd repo serves `dist/` at `/` (`web_public` app, `WEB_PUBLIC_DIR`, default `../BVTGramaConnect/dist`) and `dist/console/` at `/console/` (`web_admin` app, `WEB_ADMIN_DIR`, default `../BVTGramaConnect/dist/console`) while DEBUG is on.
- **Production:** the BackEnd repo's `deploy/deploy.sh` clones this repo to `/srv/gramaconnect/web` (setting `REPO_WEB`), builds it once, and copies `dist/` (without `console/`) to the web root's `public` folder and `dist/console/` to its `console` folder. Nginx serves `/` and `/console/` from those two folders and proxies `/api/` to Gunicorn. Everything is on one domain, so both apps call the API with relative URLs and need no CORS.
